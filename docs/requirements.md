# データ取り効率化Webアプリケーション 要件定義書

## 1. 文書概要

本書は、AI学習用データ取得におけるX線検査装置でのデータ撮像・収集作業を効率化するWebアプリケーションの要件を整理したものである。

本アプリは、データ取り要項の作成、撮像条件の組み合わせ表作成、撮像進捗の管理、撮像時間の見積もりを支援することを目的とする。

本書の粒度は、企画・要件整理レベルとする。  
詳細なDB設計、API設計、画面レイアウト詳細、運用設計は後続工程で検討する。

---

## 2. 背景

AI学習に使用するデータを取得するため、X線検査装置を用いた撮像・収集作業が発生している。

現状、データ取りを実施する際には、撮像条件や取得対象を整理したデータ取り要項を作成する必要がある。  
しかし、自分でデータを撮像する場合、または他者にデータ取りを依頼する場合のいずれにおいても、データ取り要項の作成に手間がかかっている。

また、撮像条件の組み合わせが増えると、以下の課題が発生する。

- 撮像条件の組み合わせ整理に時間がかかる
- どの条件を撮像済みか、未撮像かが分かりにくい
- 撮像作業全体の進捗が見えにくい
- 撮像に必要な工数を事前に見積もりにくい
- 複数人で同じデータ取り要項を扱う際に、進捗状況を共有しにくい

これらの課題を解消するため、データ取り要項の作成と撮像進捗管理を一体化したWebアプリケーションを構築する。

---

## 3. 目的

本アプリの目的は、AI学習用データ取得におけるデータ撮像・収集作業を効率化することである。

具体的には、以下を実現する。

- ユーザーが任意の撮像条件項目を定義できるようにする
- データ取り要項作成時に、必要な条件項目と水準を選択・入力できるようにする
- 入力された因子・水準から条件組み合わせ表を自動生成する
- 条件表をデータ取り要項としてアプリ画面上で閲覧・利用できるようにする
- 条件ごとの撮像回数、ステータス、見積撮像時間を管理できるようにする
- 撮像済み件数、全体進捗率、要確認件数をリアルタイムに確認できるようにする
- 複数人が同じデータ取り要項を参照・編集できるようにする

## 4. 適用する考え方

### 4.1 アプリ自体をデータ取り要項とする

本アプリでは、Markdown、Excel、PDFなどの外部ファイル出力をMVP範囲には含めない。  
アプリ画面上でデータ取り要項を作成・閲覧・更新できることを前提とする。

### 4.2 条件表に表示される行を撮像対象とする

条件組み合わせ表に表示されている行は、すべて撮像対象とする。  
そのため、「撮る／撮らない」の列は設けない。

不要な条件行は、条件組み合わせ表から削除することで撮像対象外とする。

### 4.3 条件項目はユーザー定義とする

撮像条件は固定項目として設計しない。  
ユーザーがアプリ設定画面で条件項目を追加・編集・削除できるようにする。

ただし、工数見積もりに必要な以下2項目は初期条件として用意し、削除不可とする。

- 投影枚数
- 露光時間

### 4.4 条件項目の形式は「選択肢」と「値」に絞る

条件項目の入力形式は、以下2種類とする。

| 形式 | 内容 | 例 |
|---|---|---|
| 選択肢 | ユーザーが候補値を文字列として登録する | 照射角度：`30°`, `45°` |
| 値 | 数値範囲、刻み幅、単位を設定する | 管電圧：50〜300、10刻み、kV |

ON/OFFは選択肢形式で扱う。  
例：`ON`, `OFF`

### 4.5 工数見積もりは純粋な撮像時間のみを対象とする

見積撮像時間は、投影枚数、露光時間、撮像回数から算出する。  
段取り時間、装置操作時間、再構成時間、サンプル交換時間、条件変更時間はMVPでは見積対象外とする。

## 5. 利用者

本アプリの主な利用者は、X線検査装置を用いてAI学習用データの撮像・収集を行う開発メンバーとする。

利用者は、以下の作業を行う。

- アプリ設定で条件項目を登録する
- データ取りタスク発生時にデータ取り要項を作成する
- 必要な条件項目を選択する
- 条件項目ごとの水準を入力する
- 条件組み合わせ表を生成する
- 撮像完了後にステータスを更新する
- 進捗状況を確認する

なお、自分で撮像する場合と他者に依頼する場合があるが、MVPでは利用シーンの違いとして扱い、専用機能は設けない。

## 8. 用語定義

| 用語 | 定義 |
|---|---|
| データ取り | AI学習に使用するデータをX線検査装置で撮像・収集する作業 |
| データ取り要項 | データ取り時に必要な条件、注意事項、条件組み合わせ表、進捗をまとめたもの |
| 計画名 | データ取り要項を識別するための名称 |
| 注意事項 | データ取り作業時に確認すべき補足事項、作業上の注意、依頼内容など |
| 条件項目 | データ取り時に使用する条件の項目名。例：管電圧、照射角度、投影枚数 |
| 形式 | 条件項目の入力形式。選択肢または値 |
| 選択肢 | あらかじめ登録された文字列候補。例：`30°`, `45°`, `ON`, `OFF` |
| 値 | 数値として入力する条件。最小値、最大値、刻み幅、単位を持つ |
| 因子 | データ取り要項作成時に選択する条件項目 |
| 水準 | 因子に対して設定する具体値または選択肢 |
| 条件組み合わせ表 | 選択した因子と水準から自動生成される撮像対象条件の一覧 |
| 撮像回数 | 同一条件を何回撮像するかを示す回数 |
| 見積撮像時間 | 投影枚数、露光時間、撮像回数から算出する純粋な撮像時間 |
| ステータス | 条件行ごとの撮像状態。未着手、撮像済み、要確認の3種類 |
| 進捗率 | 撮像済み件数を全件数で割った割合 |
| 要確認 | 撮像済みまたは作業中の条件のうち、何らかの確認が必要な状態 |

## 9. 情報構造

本アプリで扱う情報構造は、以下の階層とする。

```text
アプリ設定
└── 条件項目
    ├── 条件名
    ├── 形式
    ├── 選択肢情報
    └── 値情報

データ取り要項
├── 計画名
├── 注意事項
├── 使用する条件項目
├── 条件項目ごとの水準
└── 条件組み合わせ表
    ├── 条件値
    ├── 撮像回数
    ├── 見積撮像時間
    └── ステータス
```

### 9.1 条件項目

条件項目は、アプリ設定で管理する。  
データ取り要項作成時には、登録済みの条件項目から今回使用する項目を選択する。

### 9.2 データ取り要項

データ取りタスクごとに作成される単位とする。  
データ取り要項には、計画名、注意事項、使用条件、水準、条件組み合わせ表を持つ。

### 9.3 条件組み合わせ表

条件組み合わせ表は、データ取り要項に紐づく。  
表に存在する行は、すべて撮像対象とする。

条件表生成後、各行の条件値は直接編集不可とする。  
不要な条件行は削除可能とする。

## 10. 機能要件

### 10.1 アプリ設定機能

#### 10.1.1 条件項目の登録

ユーザーは、アプリ設定画面で条件項目を登録できる。

登録項目は以下とする。

| 項目 | 内容 |
|---|---|
| 条件名 | 条件項目の名称 |
| 形式 | 選択肢または値 |
| 選択肢 | 形式が選択肢の場合に登録する候補値 |
| 最小値 | 形式が値の場合に設定する入力可能な最小値 |
| 最大値 | 形式が値の場合に設定する入力可能な最大値 |
| 刻み幅 | 形式が値の場合に設定する入力刻み |
| 単位 | 形式が値の場合に設定する単位 |

#### 10.1.2 条件項目の編集

ユーザーは、登録済み条件項目を編集できる。

編集対象は以下とする。

- 条件名
- 形式
- 選択肢
- 最小値
- 最大値
- 刻み幅
- 単位

ただし、既存のデータ取り要項で使用中の条件項目を編集した場合の扱いは未確定事項とする。

#### 10.1.3 条件項目の削除

ユーザーは、不要な条件項目を削除できる。

ただし、以下の条件項目は削除不可とする。

- 投影枚数
- 露光時間

既存のデータ取り要項で使用中の条件項目を削除できるかは、未確定事項とする。

#### 10.1.4 初期条件項目

以下の条件項目は、初期登録済みかつ削除不可とする。

| 条件項目 | 形式 | 用途 |
|---|---|---|
| 投影枚数 | 値 | 見積撮像時間の算出 |
| 露光時間 | 値 | 見積撮像時間の算出 |

---

### 10.2 データ取り要項一覧機能

ユーザーは、作成済みのデータ取り要項を一覧表示できる。

一覧に表示する情報の候補は以下とする。

| 表示項目 | 内容 |
|---|---|
| 計画名 | データ取り要項の名称 |
| 作成日時 | 要項を作成した日時 |
| 更新日時 | 最終更新日時 |
| 進捗 | 撮像済み件数 / 全件数 |
| 進捗率 | 撮像済み件数に基づく全体進捗率 |
| 要確認件数 | ステータスが要確認の件数 |

---

### 10.3 データ取り要項作成機能

ユーザーは、データ取りタスクが発生した際に、データ取り要項を作成できる。

作成時に入力する固定項目は以下とする。

| 項目 | 内容 |
|---|---|
| 計画名 | データ取り要項を識別する名称 |
| 注意事項 | 作業上の注意、補足、依頼事項など |

注意事項は複数行テキストを想定する。

---

### 10.4 条件選択・水準入力機能

ユーザーは、データ取り要項作成時に、アプリ設定で登録済みの条件項目から今回使用する条件項目を選択できる。

選択した条件項目に対して、水準を入力する。

#### 10.4.1 選択肢形式の水準入力

形式が選択肢の条件項目では、登録済みの選択肢から今回使用する水準を選択する。

例：

| 条件項目 | 登録済み選択肢 | 今回使用する水準 |
|---|---|---|
| 照射角度 | `30°`, `45°`, `60°` | `30°`, `45°` |

#### 10.4.2 値形式の水準入力

形式が値の条件項目では、設定された最小値、最大値、刻み幅、単位に従って今回使用する水準を入力する。

例：

| 条件項目 | 設定範囲 | 刻み幅 | 単位 | 今回使用する水準 |
|---|---:|---:|---|---|
| 管電圧 | 50〜300 | 10 | kV | 150, 300 |
| 露光時間 | 1〜1000 | 1 | ms | 100, 200 |

範囲外の値、刻み幅に合わない値は入力エラーとする。

---

### 10.5 条件組み合わせ表生成機能

ユーザーが選択した因子と水準をもとに、条件組み合わせ表を自動生成する。

条件組み合わせ表は、全組み合わせを生成する。

例：

| 因子 | 水準 |
|---|---|
| 管電圧 | 150, 300 |
| 照射角度 | `30°`, `45°` |
| 露光時間 | 100, 200 |

上記の場合、2 × 2 × 2 = 8行を生成する。

条件表に表示される行は、すべて撮像対象とする。

---

### 10.6 条件組み合わせ表編集機能

条件組み合わせ表生成後、ユーザーは不要な行を削除できる。

| 操作 | 可否 |
|---|---|
| 行削除 | 可 |
| 条件値の直接編集 | 不可 |
| 行追加 | 未確定 |
| 再生成 | 未確定 |

条件値を変更したい場合は、原則として水準設定を変更し、条件組み合わせ表を再生成する想定とする。

---

### 10.7 撮像回数設定機能

ユーザーは、条件組み合わせ表の各行に対して撮像回数を設定できる。

撮像回数は、同一条件を何回撮像するかを示す。  
初期値は1回とする。

撮像回数は、見積撮像時間の算出に使用する。

---

### 10.8 見積撮像時間算出機能

条件組み合わせ表の各行に対して、見積撮像時間を算出する。

見積撮像時間は、純粋な撮像時間のみを対象とする。

計算式は以下とする。

```text
見積撮像時間 = 投影枚数 × 露光時間 × 撮像回数
```

露光時間の単位をmsとして扱う場合、秒換算は以下とする。

```text
見積撮像時間[秒] = 投影枚数 × 露光時間[ms] × 撮像回数 ÷ 1000
```

合計見積撮像時間は、条件組み合わせ表に存在する全行の見積撮像時間を合算する。

MVPでは、以下の時間は見積対象外とする。

- 段取り時間
- 装置操作時間
- 再構成時間
- サンプル交換時間
- 条件変更時間

---

### 10.9 ステータス管理機能

ユーザーは、条件組み合わせ表の各行に対してステータスを設定できる。

ステータスは以下3種類とする。

| ステータス | 意味 |
|---|---|
| 未着手 | まだ撮像していない状態 |
| 撮像済み | 撮像が完了した状態 |
| 要確認 | 撮像結果、条件、作業内容などに確認が必要な状態 |

ステータス変更の操作方法は、プルダウンまたはボタン切替を候補とする。  
MVPでの具体的なUI操作は未確定事項とする。

---

### 10.10 進捗表示機能

本アプリは、条件組み合わせ表のステータスに基づき、進捗を表示する。

表示内容は以下とする。

| 表示項目 | 内容 |
|---|---|
| 撮像済み件数 / 全件数 | ステータスが撮像済みの件数と、条件表の全行数 |
| 全体進捗率 | 撮像済み件数 ÷ 全件数 |
| 要確認件数 | ステータスが要確認の件数 |

要確認は進捗率には含めず、別表示とする。

---

### 10.11 複数人編集機能

複数人が同じデータ取り要項を閲覧・編集できることを前提とする。

特に、条件組み合わせ表のステータス変更は、複数人が同じ要項を扱う状況で発生する。

MVPでは、以下の要件を満たすことを目指す。

- 複数人が同じデータ取り要項を開ける
- 各ユーザーが条件行のステータスを更新できる
- 更新内容が他ユーザーにも反映される

リアルタイム同期方式、更新競合時の扱い、排他制御方式は未確定事項とする。

## 14. 非機能要件

### 14.1 操作性

本アプリは、開発メンバーがデータ取り時に使用するため、簡単かつ直感的に操作できることを重視する。

要件は以下とする。

- 条件項目の選択と水準入力が分かりやすいこと
- 条件組み合わせ表の生成手順が分かりやすいこと
- 撮像済みステータスの更新が容易であること
- 進捗状況が一目で分かること
- 条件表に表示される行が撮像対象であることが明確であること

### 14.2 性能

条件組み合わせ表は最大10,000行程度を想定する。

要件は以下とする。

- 10,000行程度の条件表を扱えること
- 条件表表示時の操作性が著しく低下しないこと
- ステータス変更時に進捗が速やかに更新されること

必要に応じて、テーブル仮想化、ページング、検索・フィルタなどを後続工程で検討する。

### 14.3 複数人利用

本アプリは、複数人が同じデータ取り要項を扱うことを前提とする。

要件は以下とする。

- 複数人が同じ要項を閲覧できること
- 複数人が同じ要項のステータスを更新できること
- 更新内容が他ユーザーにも反映されること

同時編集時の競合制御方式は未確定事項とする。

### 14.4 利用環境

本アプリは社内ネットワーク内で完結して利用する。

要件は以下とする。

- 外部インターネット公開を前提としない
- 社内ネットワーク内のPCブラウザから利用できる
- Next.jsをサーバー稼働して常駐させる

### 14.5 データ保全

データ取り要項、条件組み合わせ表、ステータス情報はSQLiteに保存する。

要件は以下とする。

- 作成済み要項が保存されること
- ステータス変更が保存されること
- ブラウザを閉じてもデータが保持されること

バックアップ方式は未確定事項とする。

### 14.6 セキュリティ

MVPでは権限管理は行わず、全員が同一権限で操作できるものとする。

認証・ログインの要否は未確定事項とする。

## 15. 想定利用フロー

### 15.1 初期設定フロー

1. ユーザーがアプリ設定画面を開く
2. 条件項目を登録する
3. 条件項目ごとに形式を設定する
4. 選択肢形式の場合、候補値を登録する
5. 値形式の場合、最小値、最大値、刻み幅、単位を設定する
6. 投影枚数、露光時間は初期条件として用意されている

### 15.2 データ取り要項作成フロー

1. データ取りタスクが発生する
2. ユーザーがデータ取り要項を新規作成する
3. 計画名を入力する
4. 必要に応じて注意事項を入力する
5. アプリ設定で登録済みの条件項目から、今回使用する条件項目を選択する
6. 条件項目ごとに水準を入力する
7. 条件組み合わせ表を自動生成する
8. 不要な条件行があれば削除する
9. 各行の撮像回数を設定する
10. 合計見積撮像時間を確認する
11. データ取りを開始する

### 15.3 データ取り実施フロー

1. ユーザーが組み合わせ表画面を開く
2. 条件表を確認しながら撮像を行う
3. 撮像が完了した条件行のステータスを撮像済みに変更する
4. 確認が必要な条件行は要確認に変更する
5. ステータス変更に応じて進捗率と件数が更新される
6. 全条件の撮像状況を確認する

### 15.4 複数人利用フロー

1. 複数人が同じデータ取り要項を開く
2. 各ユーザーが担当した条件行のステータスを更新する
3. 更新内容が保存される
4. 他ユーザーも進捗状況を確認できる

リアルタイム反映の方式は、後続工程で検討する。

## 17. 設計方針まとめ

本アプリは、AI学習用データ取得におけるX線検査装置での撮像・収集作業を効率化するためのWebアプリケーションである。

設計方針は以下とする。

- アプリ画面自体をデータ取り要項として扱う
- データ取り要項は、計画名、注意事項、条件組み合わせ表を中心に構成する
- 条件項目は固定化せず、ユーザーがアプリ設定で自由に定義できるようにする
- 条件項目の形式は、選択肢と値の2種類に絞る
- 投影枚数と露光時間は、見積撮像時間算出に必要なため初期条件かつ削除不可とする
- 要項作成時に、使用する条件項目と水準を選択・入力する
- 因子と水準から条件組み合わせ表を自動生成する
- 条件表に表示される行は、すべて撮像対象とする
- 不要な条件行は削除で対応する
- 条件表生成後、条件値の直接編集は行わない
- 各条件行に撮像回数、見積撮像時間、ステータスを持たせる
- 見積撮像時間は、投影枚数、露光時間、撮像回数から算出する
- 進捗は、撮像済み件数 / 全件数、全体進捗率、要確認件数で表示する
- PC利用、社内ネットワーク内利用、複数人利用を前提とする
- 技術スタックは、Next.js、TypeScript、Tailwind CSS、SQLiteを前提とする
- MVPでは、簡単かつ直感的に操作できることを重視する

以上。
